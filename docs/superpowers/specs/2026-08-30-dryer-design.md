# Сушилка для фруктов и овощей (модуль `dryer`) — дизайн

Версия дизайна: 2026-08-30. Статус: **реализовано (ветка `feat/dryer`, 2026-08-30);
стендовые проверки — см. план, Task 19.**

План реализации — `docs/superpowers/plans/2026-08-30-dryer.md`.

### Отклонения, принятые при реализации

- `runs.started_by` принимает и значение `'recovered'` — сушка уже шла, когда сервис
  поднялся; `startedAt` в этом случае восстанавливается из `run_elapsed`.
- Старт с несуществующим `presetId` → `404 preset_not_found` (MCP-инструмент ищет пресет
  по имени сам и отвечает `isError` с текстом «Пресет не найден: …»).
- MCP `dryer_start`/`dryer_stop` требуют `admin` + `write` (как REST `/runs`);
  `dryer_upsert_preset` тоже требует `admin` + `write`, хотя REST-маршруты пресетов
  проверяют только роль `admin` — в MCP все инструменты записи спрятаны за одним общим
  правилом.
- Строки `persistence` в конфиге mosquitto не повторяются в `conf.d`: они уже есть в
  дефолтном `/etc/mosquitto/mosquitto.conf` на Debian.
- Симулятор (`node/mock.ts`) пересчитывает выходы сразу на `START`/`STOP`, а не только на
  очередном шаге времени; остывание (cooldown) он оставляет только на реальный шаг
  времени.
- `RunManager.tick()` никогда не открывает сушку кнопкой/восстановлением в том же тике,
  где он застал наш собственный ожидающий `START` (`pendingStart`).
- Правило `fault:heater` в прошивке — физический критерий «пластина холоднее камеры»,
  это уже отражено в §7.
- Остывание ограничено 10 минутами безусловно — уже в §7.

## 1. Цель

Собрать из готового алюминиевого корпуса и набора комплектующих сушилку для фруктов,
овощей, грибов и трав, которая:

- держит в камере заданную температуру **до 60 °C** (с запасом до 75 °C для мяса и пастилы);
- **управляет влажностью**: вытяжка гонит тем сильнее, чем больше влаги отдаёт продукт, и
  сушка **останавливается сама**, когда продукт перестал отдавать влагу;
- управляется из единого веб-интерфейса `sweethome` — пресеты для разных продуктов, история
  сушек с графиками, уведомления — и доступна LLM-агентам через общий MCP;
- **не зависит от малины во время сушки**: нагрев, вентиляция и защита живут в самой ноде.

## 3. Принятые решения

| Развилка | Решение | Почему |
|---|---|---|
| Что значит «контроль влажности» | Вытяжка по влажности **и** автостоп по влажности | Только показывать — мало; автостоп — главная польза автоматизации |
| Сценарий запуска | Пресеты (продукт → температура, максимум часов), редактируемые; плюс «свои параметры» | Многоступенчатые программы — усложнение без подтверждённой нужды |
| Прошивка и связь | **ESPHome + MQTT**, брокер mosquitto на малине | Так же решено в спеке отопления; сушилка становится пилотом инфраструктуры |
| Кто что делает | **Нода — физика, малина — смысл** (§4) | Безопасность и температура не должны зависеть от WiFi; автостоп — алгоритм, который будут подбирать, ему место в TypeScript с тестами |
| Питание низковольтной части | Один адаптер **12 В ≥ 2 А** → Mini560 (5 В на ESP32) и повышающий (24 В на вентиляторы) | Одна сетевая часть; повышающий уже есть; запасной 12-вольтовый вентилятор пригоден |
| Физические органы | **Кнопка + светодиод**, без экрана | Экран 1602 отложен, ножки под него зарезервированы |
| Уведомления | Только веб (таблица событий) | Telegram — отдельным шагом, потребителем той же таблицы |
| Нагрев | Начинаем с одного коврика, **измеряем**; этап 2 — греющий кабель по стенкам параллельно на то же SSR (§6) | 250 Вт для такого объёма — на грани (§6) |
| Права | Смотреть — любая роль; старт/стоп, пресеты, настройки — `admin` (+ скоуп `write` для токенов) | Как у остальных модулей |

## 4. Топология и разделение ответственности

```
┌─ Нода сушилки  ESP32-WROOM-32 ───────────────┐
│  SHT41 «камера»  (I²C №1, внутри, наверху)    │
│  SHT41 «комната» (I²C №2, снаружи, у забора)  │   WiFi
│  NTC пластины    (ADC)                        │ ──MQTT──▶ ┌─────────────┐
│  SSR → нагреватель 220 В   (медленный ШИМ)    │           │  Mosquitto  │
│  MOSFET → циркуляция 120мм (вкл/выкл)         │◀──────────┤   на Pi     │
│  MOSFET → вытяжка 80мм     (ШИМ) + тахометр   │           └──────┬──────┘
│  кнопка, светодиод                            │                  │
└───────────────────────────────────────────────┘        ┌─────────┴──────────┐
                                                         │ модуль dryer       │
                                                         │ в sweethome        │
                                                         │ пресеты, автостоп, │
                                                         │ история, SQLite    │
                                                         └─────────┬──────────┘
                                                                   │
                                                   раздел /dryer единого веба, /mcp
```

| Нода (ESPHome) | Модуль на Pi |
|---|---|
| PID по температуре камеры → медленный ШИМ на SSR | Пресеты (имя, группа, температура, максимум часов, флаг автостопа) |
| Циркуляция: всю сушку + остывание, пока пластина > 50 °C | Старт/стоп из веба и MCP; сушки — записи с началом, концом и причиной |
| Вытяжка по «избытку влажности», параметры из `cfg/*`; **температура важнее продува** (§7) | **Автостоп**: избыток мал и держится → `STOP` |
| Избыток влажности считает сама (оба датчика у неё) | История замеров, графики по сушке |
| Защита: пластина > 110 °C, датчик молчит, нагрев не греет, вытяжка встала, камера > 85 °C → нагрев выкл, `fault` | События для веба (готово / ошибка / нода пропала / вернулась / перезапуск) |
| Таймер `max_minutes` — досушивает без Pi и выключается | Перезапуск сушки после перезагрузки ноды |
| Кнопка, светодиод | MCP-инструменты |

**Избыток влажности** — ключевая величина, на ней держатся вытяжка и автостоп. Комнатный
воздух, нагретый до температуры камеры, имел бы какую-то влажность сам по себе (зимой
~5 %, летом ~10 % при 60 °C). Всё, что выше — влага, которую отдаёт продукт:

```
excess = RH_камеры − RH(комнатный воздух, нагретый до T_камеры)
```

Вторая величина считается через формулу Магнуса: абсолютная влажность комнаты
(из `ambient_temperature`, `ambient_humidity`) пересчитывается в относительную при
`chamber_temperature`. Пока продукт мокрый, избыток 20–40 пунктов; сухой — около нуля.
Комнатный датчик даёт точку отсчёта, поэтому правило одинаково работает сырым летом и сухой
зимой. Формула одна и та же в прошивке (для вытяжки) и в TypeScript (для тестов и графика).

**Ноде не нужен «пульс» от Pi.** Во время сушки от Pi требуется только `STOP`. Если Pi
молчит — нода ничего не меняет: досушивает до таймера и выключается. Лестницы деградации
и heartbeat, как в отоплении, здесь нет — это следствие правильно выбранной границы.

## 5. Контракт MQTT

Префикс `dryer/`. Нода публикует средствами ESPHome, всё retained; `status` — Last Will.
**Все сенсоры уходят каждые 10 с** — это и значения, и признак жизни для Pi.

**Нода публикует:**

| Топик | Содержимое |
|---|---|
| `dryer/status` | `online` / `offline` (LWT) |
| `dryer/sensor/chamber_temperature/state` | °C, камера |
| `dryer/sensor/chamber_humidity/state` | %RH, камера |
| `dryer/sensor/ambient_temperature/state` | °C, комната |
| `dryer/sensor/ambient_humidity/state` | %RH, комната |
| `dryer/sensor/plate_temperature/state` | °C, пластина (NTC) |
| `dryer/sensor/humidity_excess/state` | пункты %RH, избыток |
| `dryer/sensor/heater_duty/state` | 0…100 %, сколько греем |
| `dryer/sensor/exhaust_duty/state` | 0…100 %, вытяжка |
| `dryer/sensor/exhaust_rpm/state` | об/мин по тахометру |
| `dryer/sensor/run_elapsed/state` | секунд с начала сушки, `0` если стоит |
| `dryer/sensor/setpoint/state` | °C — уставка, которую нода **реально** использует |
| `dryer/sensor/max_minutes/state` | предел длительности, который нода реально использует |
| `dryer/sensor/uptime/state` | секунд с загрузки — по нему Pi замечает перезагрузку |
| `dryer/text_sensor/state/state` | `idle` / `heating` / `drying` / `cooldown` / `fault` |
| `dryer/text_sensor/stop_reason/state` | почему остановились последний раз: `command` / `button` / `timeout` / `fault:plate_overheat` / `fault:overheat` / `fault:sensor` / `fault:heater` / `fault:exhaust` |
| `dryer/binary_sensor/heater/state` | `ON` / `OFF` — SSR открыто (ШИМ > 0) |
| `dryer/binary_sensor/circulation/state` | `ON` / `OFF` — циркуляция крутится |

`heating → drying` переключается, когда камера впервые дошла до уставки: полезно для
графика («разогрев 25 мин») и для автостопа (в разогреве он не работает). `cooldown` —
нагрев выключен, циркуляция гонит воздух, вытяжка 50 %, пока пластина не остынет до
50 °C; потом `idle`.

**Нода подписана:**

| Топик | Retain | Содержимое |
|---|---|---|
| `dryer/cmd/run` | **нет** | `START` / `STOP` |
| `dryer/cfg/setpoint` | да | °C, уставка (35…75) |
| `dryer/cfg/max_minutes` | да | предел длительности (30…2880) |
| `dryer/cfg/exhaust_min` | да | %, минимум вытяжки во время сушки (20…100) |
| `dryer/cfg/exhaust_gain` | да | %/пункт избытка (0…20) |

`cfg/*` нода кэширует во флеш (`restore_value: true`): кнопка на корпусе запускает сушку с
последней уставкой даже без Pi. `cmd/run` не retained намеренно: устаревший `START` от
мёртвого Pi не должен запускать нагрев после перезагрузки ноды.

**После перезагрузки нода всегда в `idle` с выключенными выходами.** Если это случилось
посреди сушки, Pi видит это по `uptime` и переотправляет `START` (§8). Кнопка на корпусе
топиков не добавляет: Pi узнаёт о ней по смене `state` без своей команды.

## 6. Железо

### Где что стоит

- **Нагреватель** клеится на **нижнюю** сторону пластины: пластина греет вверх всей
  площадью, на силикон не капает сок. Над пластиной, на нижнем кронштейне — съёмный
  поддон/фольга **меньше** пластины, чтобы капли не жарились на металле, а воздух проходил
  по краям.
- **Заборные щели** — внизу боковых стенок отсека нагревателя, ~2 × 10 см с двух сторон,
  пассивные. Сколько воздуха идёт через камеру — решает только вытяжка.
- **Циркуляция (120 мм, 2 провода)** — внутри отсека нагревателя, на боковой стенке, дует
  **вдоль** пластины. Она в горячем воздухе (обычные вентиляторы рассчитаны до 70 °C),
  ресурс будет меньше — второй 120-й в запас. Снаружи на заборе её ставить нельзя: тогда она
  гонит воздух сквозь камеру постоянно, и управление вытяжкой теряет смысл.
- **Вытяжка (80 мм, 3 провода)** — в крышке или вверху задней стенки, выдувает наружу.
- **SHT41 «камера»** — над верхней полкой, в потоке к вытяжке, на кабеле 50–70 см (I²C на
  100 кГц). Провода **силиконовые**, не ПВХ.
- **SHT41 «комната»** — снаружи, у заборной щели, не на горячей стенке и не над коробкой
  электроники.
- **Коробка электроники** — снаружи горячего объёма: в цокольном ярусе каркаса или на
  задней стенке. SSR — на металлическую площадку каркаса.

### Стенки

Снаружи фанеры — утеплитель **≥ 20 мм**, фольгированный PIR или минвата. **Не пенопласт и не
XPS**: они размягчаются при 75–80 °C, а стенки отсека нагревателя будут горячее. Профиль
каркаса снаружи по возможности тоже закрыть — это мостик холода.

Внутри фанеры — **алюминиевый скотч** с клеем на ≥ 120 °C (вентиляционный), стыки внахлёст
1–2 см, прикатать. Он даёт пароизоляцию с тёплой стороны (иначе влажный воздух идёт в фанеру
и утеплитель), моющуюся поверхность и отражение излучения пластины обратно в камеру. Фольга
токопроводящая и через каркас окажется на потенциале рамы — это хорошо, потому что рама
заземлена: внутренняя оболочка становится частью заземлённого корпуса. Требование одно: ни
один провод 220 В не идёт по фольге без изоляции; вывод нагревателя — через втулку,
клеммники — снаружи.

### Баланс тепла — почему нагреватель «на грани»

Для 60 °C в камере при 22 °C в комнате:

| Куда уходит тепло | Сколько |
|---|---|
| Через стенки (2 м²) при утеплителе 20 мм | ~100 Вт |
| То же при 10 мм | ~170 Вт |
| Каркас — мостик холода | +20–40 Вт |
| **Продув**: каждые 10 м³/ч воздуха, нагретого с 22 до 60 °C | **~130 Вт** |
| Испарение воды из продукта | всё, что осталось |

80-мм вытяжка на полной даёт через полки и щели порядка 20–30 м³/ч — 250–380 Вт только на
подогрев воздуха. Бытовые сушилки с похожей площадью полок — 400–600 Вт. Значит, 250 Вт
**будут работать**, но медленнее, и при двух условиях: утеплитель ≥ 20 мм и правило
«вытяжка уступает температуре» в прошивке (§7). Первая сушка покажет правду по
`heater_duty` и времени разогрева (§12) — и тогда решение об этапе 2.

### Этап 2 нагрева — греющий кабель по стенкам (если понадобится)

Резистивный кабель **постоянной мощности** (не саморегулирующийся — тот при 60 °C сам
сбрасывает мощность): кабель тёплого пола фиксированной длины или карбоновый провод
12K/24K, отрезаемый под мощность `P = 220² / (Ом/м × длина)`. Ориентир 15–20 Вт/м, 8–12 м →
150–250 Вт добавки; итого ~450–500 Вт ≈ 2.2 А. Преимущество перед заменой коврика: греет
там, где тепло теряется, и выравнивает температуру по высоте.

Условия: кабель **на листе тонкого алюминия** на внутренней стороне стенки (не на фанере и не
на утеплителе — поверхность кабеля 80–120 °C), металлические стяжки или алюминиевый скотч;
змейка с шагом, не ближе 3–5 см к углам и стыкам; **свой KSD301 90–100 °C** на листе
последовательно с кабелем; параллельно ковриком на то же SSR. В прошивке и модуле ничего не
меняется. Альтернатива — коврик 300 × 300 мм / 500 Вт на ту же пластину.

### Сеть 220 В — обязательная часть

```
L ──[предохранитель 3 А]──[SSR 1–2]──┬──[KSD301 125 °C NC, на пластине]──── коврик ──┐
                                     └──[KSD301 100 °C NC, на листе]────── кабель* ──┤
N ────────────────────────────────────────────────────────────────────────────────────┘
PE ─── пластина + каркас (винт с кольцевой клеммой)
      + адаптер 12 В параллельно на L/N до SSR            * — этап 2, клеммник заложить сразу
```

- **KSD301** (биметаллический термостат, нормально замкнутый) на пластине — единственная
  защита, которая работает, если сгорело SSR (они отказывают «в замкнутое») или зависла
  прошивка. Без него не включаем.
- **Заземление пластины** обязательно: нагреватель — силикон на металле, одна микротрещина —
  и пластина под фазой.
- Предохранитель сразу **3 А** — под этап 2.

### Питание низковольтной части

```
220 В → адаптер 12 В ≥ 2 А → ┬─ Mini560 Pro → 5 В → ESP32 (VIN)
                             └─ повышающий → 24 В → вентиляторы через MOSFET
```

Земли всех модулей общие (они неизолированные). **Повышающий выставить на 24 В
мультиметром до подключения вентиляторов** и зафиксировать подстроечник каплей лака; убедиться
по маркировке чипа, что он именно повышающий (XL6009 / XL6019 / LTC1871), а не понижающий
XL4016 — внешне они одинаковые.

### Распиновка ESP32-WROOM-32 (30 пинов)

| Назначение | GPIO | Примечание |
|---|---|---|
| I²C №1 — SHT41 камера | SDA **21**, SCL **22** | |
| I²C №2 — SHT41 комната | SDA **25**, SCL **26** | второй аппаратный контроллер; у обоих SHT41 адрес 0x44, на одну шину их не повесить |
| NTC пластины | **34** (ADC1, только вход) | делитель: 10 кОм на 3V3, NTC на GND, 100 нФ с ножки на землю. ADC2 занят WiFi |
| SSR | **27** → SSR «+» (клемма 3); SSR «−» (4) → GND | 3.3 В в диапазоне 3–32 В |
| Циркуляция вкл/выкл | **32** → MOSFET-модуль | логический N-MOSFET (модуль D4184 или IRLZ44N с 10 кОм на землю) |
| Вытяжка ШИМ | **33** → MOSFET-модуль | ШИМ 25 кГц |
| Тахометр вытяжки | **35** (только вход) | подтяжка 10 кОм на 3V3; **последовательно 10 кОм + стабилитрон 3.3 В на землю** — при выключенном низовом ключе на тахометре может оказаться 24 В |
| Кнопка | **4** | на GND, внутренняя подтяжка |
| Светодиод | **16** | через 330 Ом |
| Зарезервировано под LCD 1602 | 13, 14, 17, 18, 19, 23 | не занимать (§14) |

Обходим GPIO 0/2/12/15 (управляют загрузкой) и 5 (щёлкает при старте). Диоды SS34
параллельно каждому вентилятору — страховка ключей от индуктивных выбросов при ШИМ.

Делитель NTC: 10 кОм к 3V3 выбран вместо «симметричных» 100 кОм, чтобы горячий диапазон
(80–110 °C, NTC ≈ 12…5.5 кОм) попадал в точную часть шкалы ADC (1.2–1.8 В). Холодная часть
шкалы уходит в насыщение — и это неважно: NTC здесь предел, а не регулятор. Обрыв NTC
читается как «очень холодно» при любой ориентации делителя — его ловит правило
`fault:heater` (§7), а не проверка диапазона.

## 7. Прошивка ноды (ESPHome)

Конфиг — `firmware/dryer/dryer.yaml`, секреты — `firmware/dryer/secrets.yaml` (в
`.gitignore`, рядом `secrets.example.yaml`). Сборка в Docker на машине разработки, первая
заливка по USB, дальше OTA. На малине ESPHome не ставим — памяти для компиляции мало.

- **Регулятор** — штатный `climate: pid`, датчик — SHT41 камеры, выход — `slow_pwm` с периодом
  2 с на GPIO27 (SSR коммутирует в нуле, разрешение ~1 %). Первая настройка — встроенный
  автотюнинг на реальном корпусе при 60 °C, коэффициенты потом в конфиг. Если PID
  закапризничает — откат на `climate: thermostat` с гистерезисом 1 °C.
- **Состояния**: `idle → heating → drying → cooldown → idle`, плюс `fault`. Явный конечный
  автомат в `interval: 1s` на `lambda` с глобальными переменными; свежесть входов нода
  считает сама по `millis()` в `on_value`.
- **Вытяжка во время сушки**:
  `duty = clamp(exhaust_min + excess × exhaust_gain, exhaust_min, 100)`. По умолчанию
  `exhaust_min = 25`, `exhaust_gain = 4` → избыток 19 пунктов = 100 %. Ниже 20 % не опускаемся:
  на низовом ключе вентиляторы трогаются неохотно.
- **Температура важнее продува**: если нагрев на 100 %, а камера ниже уставки на ≥ 2 °C,
  вытяжка плавно (за ~1 мин) прижимается к `exhaust_min` и отпускается обратно, когда камера
  дошла до `уставка − 0.5` — флаг с гистерезисом, а не мгновенное сравнение, иначе между
  −2 и −0.5 °C вытяжка дёргалась бы туда-сюда. Без этого регулятор в начале сушки
  проигрывает вентилятору.
- **Интегратор PID сбрасывается при каждом старте** (`climate.pid.reset_integral_term`) и при
  загрузке: ESPHome продолжает интегрировать ошибку и в режиме OFF, и без сброса каждая
  сушка начиналась бы с насыщенного интегратора и перелётом по температуре.
- **Защита — зашита, из веба не меняется.** Любая → нагрев выкл, `fault`, `cooldown`,
  причина в `stop_reason`:

| Правило | `stop_reason` |
|---|---|
| пластина > 110 °C | `fault:plate_overheat` |
| камера > 85 °C | `fault:overheat` — SSR залипло; физически спасёт KSD301, но сообщить надо |
| датчик камеры или пластины молчит 30 с / NaN / пластина вне −20…150 °C | `fault:sensor` |
| нагрев ≥ 60 % пять минут подряд, а пластина не горячее камеры хотя бы на 5 °C | `fault:heater` — нагреватель мёртв, SSR не открылось, оторван NTC (читается как «холодно»). Критерий физический, а не «пластина потеплела на 5 °C»: в установившемся режиме с мокрой загрузкой пластина уже не растёт, но живой коврик на ≥ 60 % держит её заметно горячее камеры |
| вытяжка ≥ 30 % минуту, а тахометр молчит | `fault:exhaust` — иначе избыток не упадёт никогда и автостоп будет ждать вечно |

`fault` держится, пока не придёт `STOP` или не нажмут кнопку: никто не должен перезапустить
сушилку с проблемой, не заметив её. Выходы в `fault` ведут себя как в `cooldown` (нагрев выкл,
циркуляция крутится, пока пластина > 50 °C, вытяжка 50 %) — пластину надо остудить, — но
состояние остаётся `fault`. После сброса — `cooldown`, если пластина ещё горячая, иначе `idle`.
Остывание в любом случае ограничено **10 минутами** по таймеру: если пластина не читается
(обрыв NTC — как раз частая причина `fault:sensor`), без предела вентиляторы крутились бы
вечно; а горячая, но читаемая пластина через 10 минут остывает пассивно — нагрев уже выключен.

- **Тахометр**: `pulse_counter` на GPIO35. При низовом ШИМе импульсы приходят только во
  включённой фазе, поэтому правило смотрит «есть ли импульсы вообще за окно 10 с при duty
  ≥ 30 %», а не точные обороты; `exhaust_rpm` — оценка.
- **Кнопка** (GPIO4): `idle` → `START` с уставкой из флеша; любое другое состояние → `STOP`
  (из `fault` — сброс в `cooldown`). Дребезг — `delayed_on: 50ms`.
- **Светодиод** (GPIO16): `idle` — выкл; `heating` — 1 Гц; `drying` — горит; `cooldown` —
  0.25 Гц; `fault` — 4 Гц.
- **Таймер**: `run_elapsed ≥ max_minutes × 60` → `STOP` с причиной `timeout`.
- После перезагрузки — `idle`, все выходы выкл (`restore_mode: ALWAYS_OFF`).
  `reboot_timeout: 0s` у `wifi:` и `mqtt:` — нода без сети досушивает, а не перезагружается.
- Публикация всех сенсоров — `update_interval: 10s`, независимо от изменения.

## 8. Модуль `dryer` на малине

Пакеты `modules/dryer` (`@sweethome/dryer`) и `packages/dryer-shared` (`@sweethome/dryer-shared`
— типы снапшота, пресета, сушки, настроек, общие с вебом) — по образцу `cctv` / `cctv-shared`.
Модуль реализует `HomeModule` и `McpCapable`, монтируется как `/api/dryer` + `/ws/dryer`.

| Файл | За что отвечает |
|---|---|
| `config.ts` | свои ключи в общем `server/.env` (ниже) |
| `node/mqtt.ts` | подписка на `dryer/#`, свежесть каждого значения, публикация `cfg/*` и `cmd/run`. Клиент инжектируется — тесты без брокера |
| `node/mock.ts` | **симулятор ноды** для `npm run dev`: тепловая модель первого порядка (греется к уставке, остывает), избыток убывает экспоненциально, реагирует на `START`/`STOP`/`cfg`. Без него нельзя делать веб, не включая сушилку |
| `humidity.ts` | чистая `excessHumidity(chamber, ambient)` — та же формула Магнуса, что в прошивке |
| `autostop.ts` | чистая `decideAutostop(input, cfg)` — всё решение «продукт сухой» без сайд-эффектов |
| `runs.ts` | жизненный цикл сушки: старт/стоп, кнопка, перезагрузка ноды, закрытие по причинам |
| `store.ts` | SQLite на `node:sqlite`, `server/data/dryer/dryer.db` |
| `dryer.ts` | тик раз в 10 с: собирает снапшот, гоняет `runs` и `autostop`, пишет замеры и события, рассылает WS |
| `router.ts`, `module.ts`, `mcp/` | REST, сборка, MCP-провайдер |

### Автостоп — `decideAutostop`

Вход: ряд `(ts, excess)` за последние `holdMinutes`, состояние ноды, минут с начала сушки,
`autostop_enabled` сушки, настройки. Выход: `{ stop: boolean, reason: string,
belowSince: number | null, gaps: boolean }`.

Останавливаем, когда **все** условия выполнены: состояние `drying` (не разогрев), прошло
≥ `minRunMinutes`, ряд за `holdMinutes` **без дыр** (замеры каждые 10 с, дыра — промежуток
> `staleAfterSeconds`), все точки ряда ниже `excessThreshold`. Причина — текст, готовый к
показу: «избыток влажности ниже 3 пунктов уже 30 минут». Любая дыра в данных — не
останавливаем и говорим об этом в UI: лучше пересушить на полчаса, чем остановить мокрое.

### Жизненный цикл сушки (`runs.ts`)

- **Старт из веба/MCP**: проверки — нода online, состояние `idle`, открытых сушек нет.
  Иначе `409 already_running` или `409 fault_active` (сначала стоп — чтобы ошибку увидели).
  Публикуем `cfg/setpoint`, `cfg/max_minutes`, `cfg/exhaust_min`, `cfg/exhaust_gain`
  (retained), затем `cmd/run START`, ждём до 5 с смены состояния на `heating`. Дождались —
  запись сушки создана, `200` со снапшотом. Нет — `504 node_unresponsive`, запись не создаём.
- **Стоп из веба/MCP**: `cmd/run STOP`, `end_reason = 'stopped'`. Из `fault` — тот же стоп, он же
  сброс ошибки; сушка при этом уже закрыта с `fault:*`.
- **Кнопка**: состояние ушло `idle → heating` без нашей команды → открываем сушку
  `started_by = 'button'`, `preset_name = NULL`, уставка и предел из `sensor/setpoint` и
  `sensor/max_minutes`; автостоп включён с глобальными настройками.
- **Нода остановилась сама** (`timeout`, `fault:*`, кнопка): закрываем сушку с её
  `stop_reason` (`button` → `'stopped'`), пишем событие.
- **Нода перезагрузилась посреди сушки** (`uptime` стал меньше предыдущего): если
  `now − started_at < max_minutes` — переотправляем `cfg/*` + `START`, `restarts++`, событие
  `run_restarted`; иначе закрываем как `timeout`. Не больше 3 перезапусков на сушку — дальше
  закрываем с `fault:node_reboot_loop`.
- **Нода пропала во время сушки** — сушку **не закрываем**: она, скорее всего, досушивает сама
  без WiFi. В UI — «нет связи, нода работает автономно». Закрываем как `node_lost`, только если
  молчит дольше `max_minutes + 15 мин` от старта (событие `run_lost`). Событие `node_offline` —
  через 2 минуты тишины, `node_online` — по возвращении.

### API (`/api/dryer`)

Все ответы — JSON, времена — unix ms, температуры — °C числом, `null` = «данных нет» и никогда
не подменяется нулём. Ошибки валидации — `400` с русским текстом, готовым к показу.

| Метод | Путь | Что | Кому |
|---|---|---|---|
| `GET` | `/state` | снапшот целиком | любая роль |
| `WS` | `/ws/dryer` | тот же снапшот каждый тик (10 с), первый кадр сразу | любая |
| `GET` | `/presets` | список по группам | любая |
| `POST` | `/presets` | создать | `admin` |
| `PUT` | `/presets/:id` | изменить (частично) | `admin` |
| `DELETE` | `/presets/:id` | удалить | `admin` |
| `POST` | `/runs` | старт: `{ presetId }` или `{ setpoint, maxMinutes, autostop? }` | `admin` + скоуп `write` |
| `POST` | `/runs/current/stop` | стоп / сброс ошибки | `admin` + `write` |
| `GET` | `/runs?from&to` | история сушек | любая |
| `GET` | `/runs/:id/samples` | ряды одной сушки для графика | любая |
| `GET` | `/settings` | глобальные настройки | любая |
| `PUT` | `/settings` | частичное изменение | `admin` |
| `POST` | `/events/:id/seen` | «уведомление прочитано» | любая |

```
DRYER_MQTT_PREFIX=dryer
```

Имена свои, а не общий `MQTT_URL`: тот уже занят у инвертора под Home Assistant и выключен.
Когда придёт отопление, брокерный клиент вынесем в общий пакет — сейчас это преждевременно.

**Health**: `ok`, если брокер подключён и нода была на связи < `staleAfterSeconds`; иначе
`ok: false` с `details: { broker, nodeOnline, lastSeen, state }`.

## 9. Веб-интерфейс

Раздел `/dryer/*` единого приложения (Next 15, static export), пункт «Сушилка» в общей
навигации, карточка на обзорной `/`. Обновления по WebSocket; при его падении — опрос
`GET /state` раз в 10 с. Переводы UA/RU/EN — в общий словарь `web/lib/i18n`.

**Карточка на обзоре (`/`)** — статус с одного взгляда, вся площадь — ссылка в раздел: чип
состояния (Простой / Разогрев / Сушка / Остывание / Ошибка / Нет связи), `58 → 60 °C`,
влажность и избыток, `3:12 из 14:00`, пресет, последнее непрочитанное событие.

**Главная `/dryer`:**

- Крупно температура камеры и уставка; рядом влажность камеры и **избыток**; мельче — комната,
  пластина, нагрев %, вытяжка % и об/мин.
- Управление. В простое: пресеты чипами **в трёх группах** (фрукты / овощи / остальное) +
  «Старт»; свёрнуто — «Свои параметры» (уставка 35…75 шагом 1, максимум часов, автостоп).
  Во время сушки: «Стоп», прошло/предел, строка автостопа («избыток 6.2, ждём ниже 3» / «ниже
  порога уже 12 мин из 30» / «автостоп ждёт непрерывных данных»). В ошибке: причина
  человеческим языком и «Сбросить ошибку».
- График текущей сушки на существующем `TimeChart` (uplot): температура камеры + уставка,
  избыток, нагрев %. После остановки остаётся до следующего старта.
- События: непрочитанные сверху, крестик — «прочитано»; новое по WS — тост.

**История `/dryer/history`:** таблица сушек (дата, пресет, длительность, чем закончилась,
перезапуски), клик — график по `GET /runs/:id/samples`.

**Настройки `/dryer/settings`** (admin): пресеты (группа, имя, температура, максимум, автостоп;
добавить/изменить/удалить), параметры автостопа, `exhaustMin` / `exhaustGain`. Ошибка сервера
показывается дословно, поле не сбрасывается.

### Состояния экранов

| Ситуация | Что показываем |
|---|---|
| Снапшот не пришёл | «Загрузка…», никаких нулей |
| `GET /state` ошибка | красная строка с текстом как есть, остальное не рисуем |
| Нода офлайн, сушки нет | «Нет связи с сушилкой»; «Старт» заблокирован с подписью почему |
| Нода офлайн, сушка **идёт** | янтарное «Нет связи — нода досушивает сама, остановится по таймеру не позже HH:MM»; «Стоп» активен с пометкой «дойдёт, когда связь вернётся» |
| `fault` | красная плашка с расшифровкой; «Старт» скрыт, есть «Сбросить ошибку» |
| Сушка запущена кнопкой | «Запущена кнопкой на корпусе», пресет «—» |
| Перезапуск после сброса | значок и «перезапусков: N» в строке сушки |
| Автостоп выключен | «Автостоп выключен — остановится по таймеру» |
| Данные для автостопа с дырами | «автостоп ждёт непрерывных данных» вместо счётчика минут |
| `cooldown` | «Остывание — пластина 68 °C, циркуляция работает» |
| Значение `null` | «—», не ноль; влажность при `null` скрыта, не обнулена |
| Роль `viewer` | контролы `disabled`, сверху «Только просмотр: нужна роль admin»; роль не загрузилась — считаем `viewer` |
| В истории нет сушек за период | «Сушек за период нет», пустой график не рисуем |

Расшифровки `fault:*`: `plate_overheat` — «Перегрев пластины (> 110 °C)»; `overheat` —
«Перегрев камеры (> 85 °C) — проверь реле»; `sensor` — «Датчик не отвечает»; `heater` —
«Нагреватель не греет — проверь коврик, реле и термистор»; `exhaust` — «Вытяжка не
крутится»; `node_reboot_loop` — «Нода перезагружается по кругу».

**Роли**: смотреть всё — любая; старт/стоп, пресеты, настройки — `admin`. Серверно
`/dryer/settings` — в `ADMIN_PAGES`, клиентски — в `ADMIN_PATH_PREFIXES`.

## 10. MCP

Провайдер `modules/dryer/src/mcp/` регистрируется в общем `/mcp` хоста (`McpCapable`, как у
cctv). Инструменты записи регистрируются в сессии только при скоупе `write`; `dryer_upsert_preset`
— только при роли `admin`.

| Инструмент | Что делает | Права |
|---|---|---|
| `dryer_get_state` | снапшот `structuredContent` + текст «Сушка: Яблоки, 60 °C, идёт 3 ч 12 м, камера 58.2 °C, избыток 6.2, автостоп ждёт ниже 3» | read |
| `dryer_list_presets` | пресеты по группам | read |
| `dryer_get_runs` | сушки за период: когда, пресет, длительность, чем закончились, перезапуски | read |
| `dryer_get_run_chart` | ряды одной сушки, прореженные до ≤ 200 точек | read |
| `dryer_start` | `{ preset }` или `{ setpoint, maxHours, autostop? }`; те же проверки и те же ошибки, что REST; `started_by = 'mcp:<token>'` | write |
| `dryer_stop` | стоп / сброс ошибки | write |
| `dryer_upsert_preset` | создать/изменить пресет | write + admin |

Ресурсы: `dryer://state`, `dryer://runs/recent` (последние 20). Подсказка `dryer-report` —
«как прошла последняя сушка: сколько разогревались, как падал избыток, чем закончилось, были
ли перезапуски и ошибки». В `instructions` сервера: старт включает нагреватель 220 В —
подтверждать с человеком; при `fault` не запускать, сначала выяснить причину.

## 11. Инфраструктура и деплой

**Mosquitto на малине** — разовая ручная подготовка (как `ffmpeg` для cctv), инструкция в
`docs/dryer/README.md`:

- `apt install mosquitto mosquitto-clients`; `listener 1883 0.0.0.0` (ноде нужен доступ из
  сети); `allow_anonymous false`; `persistence true` — retained переживают перезагрузку;
  `acl_file /etc/mosquitto/acl`.
- Пользователи (`mosquitto_passwd`, файл `600`, владелец `mosquitto`): `dryer-node` — пишет
  `dryer/#`, читает только `dryer/cmd/#` и `dryer/cfg/#`; `dryer-service` — читает и пишет
  `dryer/#`.
- `deploy.sh` проверяет `systemctl is-active mosquitto` и **предупреждает**, но не падает:
  инвертор и камеры без брокера работать должны, а сушилка покажет «брокер недоступен» в health.

**Сеть**: DHCP-резервации для малины и ноды на роутере; в прошивке брокер задаётся IP малины,
не mDNS.

**Прошивка**: `firmware/dryer/{dryer.yaml, secrets.example.yaml, README.md}`; `secrets.yaml`
в `.gitignore`. Сборка: `docker run --rm -v "$PWD":/config --device=/dev/ttyUSB0
ghcr.io/esphome/esphome run dryer.yaml` (первая заливка), далее `… run dryer.yaml --device <ip>`
(OTA). Бинарники в git не кладём.

**Деплой**: порядок сборки — `… → modules/cctv → packages/dryer-shared → modules/dryer →
server → web`; `deploy.sh` добавляет их `dist/` в rsync и в `npm ci -w …` на малине. Из нового
приезжает пакет `mqtt` (чистый JS). Модуль подключается в списке модулей хоста;
`/dryer/settings` — в `ADMIN_PAGES`; `/dryer` получает явную отдачу файла (как `/cctv`:
страница и родитель вложенных маршрутов одновременно). В `.env` на малине — `DRYER_*`.

Малина хрупкая по питанию (см. корневой `CLAUDE.md`): модуль не добавляет постоянной нагрузки —
один MQTT-клиент и тик раз в 10 с.

## 12. Тестирование и ввод в эксплуатацию

**jest** (по образцу cctv, всё без брокера и железа):

- `autostop.test.ts` — **приоритет**: порог, окно удержания, дыры → не останавливать,
  `minRunMinutes`, только в `drying`, выключенный автостоп, `belowSince`.
- `humidity.test.ts` — формула Магнуса на табличных значениях; тождество: комнатный воздух,
  «нагретый» до своей же температуры, даёт избыток 0.
- `runs.test.ts` — старт/стоп, запуск кнопкой, перезапуск после сброса и отказ от него по
  времени и по счётчику, `node_lost`, `timeout`, закрытие по `fault`.
- `node/mqtt.test.ts` — разбор топиков, свежесть, `cfg/*` уходят **до** `START`, `cmd` не
  retained, LWT.
- `node/mock.test.ts` — симулятор доходит до уставки, избыток убывает, `STOP` → `cooldown → idle`.
- `store.test.ts` — схема, идемпотентный посев пресетов, замеры по сушке, чистка по возрасту,
  битое поле настроек откатывается на дефолт.
- `router.test.ts` — supertest: роли и скоупы, `409`/`504`, валидация с русскими текстами.
- `mcp/tools.test.ts` — через реальный MCP-клиент по `InMemoryTransport`; write-инструменты
  невидимы без скоупа.
- `module.test.ts` — health в разных состояниях.
- веб — таблица состояний экрана (§9), каждая строка — тест; карточка обзора.

**Настольный стенд — обязателен, до установки в корпус.** Вместо нагревателя — лампа 60 Вт
через SSR, NTC в руке:

1. PID крутит лампу, состояние `heating → drying`.
2. Выдернуть датчик камеры → `fault:sensor` за 30 с; погреть NTC феном → `fault:plate_overheat`;
   снять тахометр → `fault:exhaust`; лампу выкрутить → `fault:heater` через 5 минут.
3. Убить WiFi посреди сушки → нода продолжает, Pi держит сушку открытой, при возврате всё
   сходится.
4. Передёрнуть питание ноды посреди сушки → Pi перезапускает, `restarts = 1`.
5. Кнопка: старт из простоя → Pi открыл сушку «кнопкой»; ещё раз → стоп.
6. `mosquitto_sub -t 'dryer/#' -v` показывает все сенсоры каждые 10 с.

**Первые прогоны в корпусе** — часть плана, не «потом»:

1. Пустой прогон 70 °C, 1–2 ч, вытяжка на максимум — выпарить клей скотча, утеплитель и фанеру.
2. Автотюнинг PID на 60 °C, коэффициенты — в конфиг.
3. Смотрим `heater_duty` и время разогрева → **решение по этапу 2 нагрева** (§6).
4. Кухонный термометр на нижнюю и верхнюю полку → разброс по высоте.
5. Первая реальная партия (яблоки) под наблюдением: по кривой избытка калибруем
   `excessThreshold` и `holdMinutes` — `3 / 30` сейчас догадка, а не измерение.

## 13. Критерии приёмки

- Сушилка держит 60 °C ± 2 °C с загруженными полками; автостоп останавливает партию яблок, и
  она сухая на ощупь.
- Каждое из пяти правил защиты проверено на стенде и срабатывает.
- Нода досушивает при выключенной малине и выключается по таймеру.
- Всё из таблицы состояний экрана воспроизводимо на симуляторе.
- `npm run check` зелёный; деплой не трогает инвертор и камеры; без mosquitto остальные
  модули работают, сушилка — `ok: false` с понятной причиной.

## 14. Вне первой версии

- **Экран LCD 1602** — подходит, GPIO 13/14/17/18/19/23 зарезервированы; подключение: шилд
  RS=D8, E=D9, D4–D7, 5V, GND; D10 (подсветка) не подключать; ESPHome `lcd_gpio`; кнопки шилда
  не использовать (5 В на аналоговой ноге).
- **Греющий кабель** — этап 2 нагрева (§6), клеммник и предохранитель заложены сразу.
- **Telegram** — потребитель таблицы `events`, общий для модулей.
- Многоступенчатые программы, весы под полки, датчики по полкам.
- Общий MQTT-клиент для модулей — когда придёт отопление.

## 15. Риски

| Риск | Что делаем |
|---|---|
| Нагреватель слабый | измеряем на первом прогоне; кабель или коврик 500 Вт — без переделки схемы и кода |
| Циркуляционный вентилятор в 60 °C живёт меньше | запасной есть; тахометра у него нет — следим по разбросу температур по высоте |
| ADC ESP32 врёт на ±3–5 °C по NTC | NTC — предел, а не регулятор; порог 110 °C с запасом до 130 у коврика |
| Автостоп настроен наугад | калибруется на первой партии, правится без прошивки |
| Автотюнинг PID не сойдётся | откат на `thermostat` с гистерезисом — одна правка в yaml |
| Тахометр на низовом ШИМе шумит | правило «есть ли импульсы вообще», не точные обороты |
| Повышающий выставлен не на 24 В | выставить и зафиксировать до подключения вентиляторов |
