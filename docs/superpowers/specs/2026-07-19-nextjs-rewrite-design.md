# Дизайн: переезд inverter-monitor на Next.js

Дата: 2026-07-19. Статус: одобрен пользователем (секции 1–3 подтверждены в сессии).

## Цель

Упростить дальнейшую разработку UI: React-компоненты вместо ручного DOM
(~500 строк `public/app.js`) и экосистема Next.js (App Router, HMR, роутинг).
Осознанный выбор пользователя — именно Next.js.

Планируемые фичи, под которые закладывается архитектура: графики истории
(таймсерии на Pi), уведомления/алерты (Telegram/push), больше экранов/настроек.

## Ограничения

- Деплой-цель: Raspberry Pi 3B, 1 ГБ ОЗУ, arm64, Node 24, systemd-сервис
  `inverter-monitor`, порт 3000.
- Бэкенд — проверенный долгоживущий демон: поллер serial/HID/mock, очередь
  «одна команда за раз», блокировка записи, эталон настроек, auth, MQTT.
  Его логика при переезде НЕ переписывается.
- Инвертор ещё не подключён физически — всё проверяется в mock-режиме.
- UI: дух e-ink дизайна сохраняется (дизеринг, антиква, печатные цвета,
  секторный индикатор), детали можно улучшать по ходу. i18n UA/RU/EN
  сохраняется.

## Выбранная архитектура (вариант A из трёх рассмотренных)

**Next.js static export + существующий Express-демон.**

- `next build` с `output: 'export'` собирает UI в статику `web/out/`.
- Express-демон остаётся единственным процессом на Pi и раздаёт `web/out/`
  вместо нынешней `public/`.
- Next и React в рантайм Pi не попадают.

Отклонённые альтернативы:
- **B: custom server** (поллер+WS внутри Next) — Next-runtime ~150–250 МБ на
  Pi 3B, капризные синглтоны против hot-reload, тяжёлый деплой `.next`.
- **C: два процесса** (next start + демон) — два сервиса на 1 ГБ ОЗУ,
  WS не проксируется через Next в проде.

## Структура репозитория

npm workspaces-монорепо:

```
inverter-monitor/
├── package.json          # workspaces: ["shared", "server", "web"]
├── shared/               # общие TS-типы и константы, без зависимостей
│   └── src/              # Snapshot, Settings, Meta, коды ошибок API,
│                         # таблицы приоритетов (OUTPUT_SOURCE_PRIORITY и т.п.)
├── server/               # нынешний бэкенд, переезжает почти без изменений
│   ├── src/              # index, config, inverter, server, auth, mqtt,
│   │   ├── protocol/     # protocol/ и transport/ — код байт-в-байт,
│   │   └── transport/    # меняются только импорты типов на shared
│   ├── systemd/
│   └── package.json      # express, ws, serialport, node-hid, mqtt
└── web/                  # Next.js: App Router, TS, output: 'export'
    ├── app/
    └── package.json      # next, react (на Pi не едет)
```

Решения:
- `shared/` — единственный источник типов для сервера и фронта. Изменение
  поля снапшота ловится tsc во всех местах использования.
- `git init` в корне `inverter-monitor/`. Первый коммит — текущее состояние
  до рефакторинга (точка отката), дальше — дизайн-док и работа.
- На Pi едут только `shared/`, `server/`, `web/out/` и корневые манифесты.

## Фронтенд

### Страницы (App Router)

Нынешняя одностраничка разбивается на экраны:

- `/` — дашборд: статус, кольцо заряда, карточки батарея/PV/нагрузка/сеть;
- `/settings` — таблица «Сейчас/Эталон» с drift-подсветкой, панель управления
  с блокировкой (unlock → запись → авто-relock);
- `/diagnostics` — произвольные PI30 query-команды (нынешняя панель
  «Расширенное»);
- `/login` — вход.

Общий layout: шапка со статусом соединения, e-ink навигация между экранами,
переключатель языка в подвале.

### Компоненты

Прямой порт кусков `app.js`: `BatteryRing` (SVG-сектора с дизерингом),
`StatCard`, `SettingsTable`, `ControlPanel`, `LockBanner`, `ConfirmDialog`,
`Toast`. `style.css` переносится глобальным стилем; дробление на CSS-модули —
по ходу, без потери e-ink эстетики («вспышка» на обновлении, ghosting при
потере связи — сохраняются).

### Данные

Без стейт-менеджера:
- `useSnapshot()` — WebSocket: подписка, реконнект с бэкоффом, таймер
  протухания, ghosting (порт текущей логики);
- `useMeta()`, `useBaseline()` — fetch-хуки;
- обёртка `api()` над fetch: JSON, ошибки, `401` → редирект `/login`;
- выбор WS-URL: в проде same-origin `/ws`, в dev — `ws://localhost:3000/ws`
  (хелпер, см. «Дев-флоу»).

Всё типизируется из `shared/`.

### i18n

Словари UA/RU/EN из `public/i18n.js` переезжают в типизированные TS-модули
(пропущенный ключ — ошибка компиляции). React-контекст + `useT()`. Выбор
языка в localStorage. Смена языка — без перезагрузки страницы (ре-рендер).
Серверные коды ошибок логина (`bad_password`, `rate_limited`+minutes)
переводятся на клиенте, как сейчас.

### Auth на клиенте

Схема не меняется: HttpOnly-cookie, логин POST `/api/login`. API-401 и
WS-close 4401 ведут на `/login`.

## Бэкенд — минимальные правки

1. Статика: `express.static(web/out, { extensions: ["html"] })`, чтобы
   `/settings` отдавал `settings.html`.
2. Редирект на логин: со списка `/`+`/index.html` расширяется на все
   HTML-страницы (`/`, `/settings`, `/diagnostics`); ассеты и `/login`
   открыты, как сейчас.
3. Пути: `.env` и `data/` (baseline.json, sessions.json) переезжают в
   `server/` — на Pi одноразовый перенос при деплое, содержимое не трогается.

Всё остальное (inverter, protocol, transport, mqtt, auth) — без изменений.

## Дев-флоу

`npm run dev` в корне (concurrently):
- демон в watch-режиме (tsx), mock-транспорт, auth выключен, порт 3000;
- `next dev` на 3001, rewrites `/api/*` → `http://localhost:3000`.

WebSocket через Next-rewrites не проксируется — в dev клиент подключается
напрямую к `ws://localhost:3000/ws`. Auth в dev выключен, поэтому
cross-origin-cookie проблем нет.

## Сборка и деплой

Всё собирается на машине разработчика (обе сборки — платформонезависимый JS):

```
локально: tsc → server/dist  +  next build → web/out
rsync:    корневые package.json/lock, shared/, server/{dist,package.json,systemd}, web/out/
на Pi:    npm ci -w server --omit=dev  &&  sudo systemctl restart inverter-monitor
```

- Pi больше не компилирует TS; `npm ci` нужен только для нативных модулей
  (serialport, node-hid — arm64-пребилды).
- `deploy.sh` в корне кодирует весь флоу, в конце проверяет
  `GET /api/health` после рестарта (с учётом задержки старта).
- systemd-юнит правится один раз: `ExecStart` → `server/dist/index.js`,
  `WorkingDirectory` → `server/`.

## Проверка

- Бэкенд: существующие проверки переезжают как есть — tsc, CRC-эталоны
  (`QPIGS→B7A9` и др.), раундтрипы кадров, MQTT-тест с фейк-клиентом.
- Web: `tsc --noEmit`, eslint (только изменённые файлы), `next build` как
  смоук.
- Функционально: руками против mock-демона (все сценарии: логин, блокировка,
  запись, recapture, смена языка, потеря связи). Playwright — только по
  явной просьбе пользователя.

## Риски и откат

- **UI-регрессии при порте** — сравнение со старым `public/` (остаётся в
  git-истории), сценарный чек-лист выше.
- **Пути на Pi** (`data/`, `.env`, юнит) — покрыты deploy-скриптом и
  health-check'ом.
- **Откат** — git-тег на последнем рабочем состоянии старой версии; redeploy
  предыдущего коммита возвращает всё как было.

## Вне скоупа

Сами фичи (графики истории, алерты, новые настройки) в этот рефакторинг не
входят — только архитектурная база под них. MQTT/HA-функциональность не
меняется. Подключение реального инвертора — отдельная задача (ждём адаптер).
