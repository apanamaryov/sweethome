# Индикатор источника питания: третье состояние «От солнца»

Дата: 2026-07-28. Статус: одобрено владельцем (дизайн-сессия).

## Цель

Значок в правом верхнем углу дашборда (`web/app/(app)/layout.tsx`) сейчас показывает
режим самого инвертора — регистр 201, декодированный в `decodeMode`. На практике владелец
видит там только «От сети» и «От батареи». Нужно третье состояние — **«От солнца»**.

## Почему это не читается из регистра

Список значений регистра 201 задан прошивкой: `PowerOn` / `Standby` / `Line` / `Battery` /
`Bypass` / `Charging` / `Fault`. Состояния «работаю от солнца» в нём **нет**: когда PV тянет
нагрузку, инвертор всё равно рапортует `Battery`, потому что солнце идёт через батарейную
шину. Значит, состояние надо **вычислять** из телеметрии, которая уже есть в снапшоте.

## Требования (зафиксированы с владельцем)

- **Один значок, а не два.** «От солнца» **подменяет** «От батареи», когда нагрузку тянет
  солнце. Как только PV перестаёт её покрывать — возвращается «От батареи». Отдельный
  второй индикатор в шапке не заводим: на телефоне это лишняя строка.
- **Критерий — батарея не разряжается.** Режим `Battery` + есть выработка + из банки
  ничего не течёт ⇒ нагрузку тянет только солнце. Признак снимается с одного регистра
  (232), поэтому нет рассогласования между двумя независимыми замерами, как было бы при
  сравнении `pvPower` с `acOutputActivePower`.
- **Гистерезис — два замера подряд.** При `POLL_INTERVAL_MS = 5000` это ~10 с. Отсекает
  одиночные всплески (набежавшее облако, включившийся чайник), реакция остаётся почти
  мгновенной.
- **Признак доступен не только в UI.** Владелец выбрал серверный вариант именно ради
  Home Assistant: по сущности «источник питания» должны писаться автоматизации
  («включить бойлер, когда на солнце»). Поэтому вычисление живёт на сервере и едет в
  снапшоте — в WS, REST, MQTT и MCP разом.

## Контракт (`shared/`)

`shared/src/types.ts`:

```ts
export type PowerSource = DeviceMode | "Solar";
```

и новое **обязательное** поле в `Snapshot`:

```ts
powerSource: PowerSource;
```

Обязательное, а не опциональное: тогда `tsc` сам найдёт все фикстуры и литералы снапшота,
которые нужно дополнить. Это осознанный способ не пропустить ни одного места.

### Ядро: `shared/src/source.ts` (чистый модуль)

Без БД, сети, таймеров и `Date.now()` внутри — тестируется в отрыве.

```
PV_MIN_W = 50          // Вт, отсекает ночной ноль и шум датчика
DISCHARGE_EPS_A = 0.5  // А (≈25 Вт на 51 В), шум измерения тока

instantSource(mode, status) -> PowerSource
stepSource(prev, candidate) -> SourceState
```

- `instantSource` возвращает `"Solar"`, если **все три** условия истинны:
  `mode === "Battery"`, `status.pvPower > PV_MIN_W`,
  `status.batteryDischargeCurrent <= DISCHARGE_EPS_A`. Иначе возвращает `mode` как есть.
  При `status === null` возвращает `mode`. `NaN` в любом из полей трактуется как «условие
  не выполнено» (сравнения с `NaN` дают `false`, что и требуется).
- `SourceState = { shown: PowerSource; pending: PowerSource; count: number }` —
  `shown` показывается наружу, `pending`/`count` копят подряд идущие одинаковые кандидаты.
- `stepSource(prev, candidate)`: если `candidate === prev.shown` — состояние сбрасывается
  к «ничего не ждём» (`pending = shown`, `count = 0`). Иначе счётчик кандидата растёт,
  и когда он **достигает 2**, `shown` переключается на кандидата, а счётчик обнуляется.
  То есть первый отличающийся замер только взводит ожидание, второй подряд такой же —
  переключает. Смена кандидата на полпути начинает счёт заново с 1.
- Пороги — именованные константы, экспортируются для тестов. Env-переменных не заводим:
  в отличие от солнечного окна, здесь нечего хранить в истории и нечего тюнить постфактум.

Модуль лежит в `shared`, потому что у него два потребителя: сервер считает, веб типизирует.
Тест — `shared/src/source.test.ts`; он подхватится существующим jest сервера, у которого
`shared/src` уже входит в `roots` (прецедент — `shared/src/settings.test.ts`).

## Сервер

`server/src/inverter.ts`:

- Поле класса `private sourceState: SourceState`, инициализировано `shown: "Unknown"`.
- В конце цикла поллинга: `instantSource(mode, status)` → `stepSource` → `powerSource`
  кладётся в собираемый снапшот.
- **Сброс состояния** при дисконнекте и при смене устройства — к
  `{ shown: "Unknown", pending: "Unknown", count: 0 }`. Иначе после переподключения
  всплывёт залежавшееся `"Solar"`, а гистерезис ещё и задержит его на два цикла.
- Дефолтный снапшот (поле `snapshot` класса) и «отключённая» ветка получают
  `powerSource: "Unknown"`.

Тесты — в существующий `server/src/inverter.test.ts`.

## Home Assistant (MQTT)

`server/src/mqtt.ts`:

- В массив `SENSORS`: `{ key: "power_source", name: "Источник питания",
  icon: "mdi:solar-power-variant" }`.
- В payload: `power_source: snap.powerSource`.

Дальше автодискавери заводит сущность сам — YAML не нужен. Это и есть та часть, ради
которой выбран серверный вариант.

Тест — в существующий `server/src/mqtt.test.ts`.

## MCP

Поле едет само: инструменты чтения отдают `Snapshot` целиком, отдельной работы по
инструментам нет. Точечно нужно дополнить `FAKE_SNAPSHOT` в
`mcp/src/testing/fake-gateway.ts` — иначе фикстура разойдётся с реальной схемой. Это ровно
те грабли, на которых проект уже стоял с `soc_min`/`batteryCapacity_min`, и CLAUDE.md
предупреждает о них отдельно.

## Веб

- `web/app/(app)/layout.tsx`: читать `snapshot?.powerSource ?? "Unknown"` вместо
  `snapshot?.mode`. Разметка не меняется — `className={"mode-badge mode-" + source}`,
  текст `modeLabel(t, source)`. Клиентского гистерезиса нет: его уже сделал сервер.
- `web/lib/i18n/dict.ts`: ключ `modeSolar` в три словаря — `Від сонця` / `От солнца` /
  `Solar`. Саму `modeLabel` править не нужно: она резолвит `dict["mode" + value]`.
- `web/app/globals.css`: правило `.mode-Solar` в жёлтой гамме через существующую
  `--sun-deep`, по образцу `.mode-Battery`.

## Чего эта работа осознанно не делает

- **Не пишет смену источника в журнал событий статистики.** `recorder.ts` уже логирует
  смену режима, а историю «когда было солнце» закрывает солнечное окно. Дублировать не
  нужно, и на переменной облачности это засорило бы журнал.
- **Не добавляет env-переменных.** Пороги — константы в модуле.
- **Не трогает** карточку «Солнце» на дашборде и `SolarToday`.
- **Не меняет** декодер режима `decodeMode` и карту регистров: новых регистров нет.
