# Inverter Monitor — SK-5500P-48L (локально, без облака)

Веб-приложение на TypeScript/Node.js для мониторинга и управления гибридным
инвертором **SK-5500P-48L** (семейство Voltronic / SmartESS) **напрямую, минуя
приложение SmartESS и его облако**. Работает на Raspberry Pi, отдаёт мобильный
веб-интерфейс и REST/WebSocket API в локальную сеть.

---

## 1. Краткий ответ на исходный вопрос

Да — данные инвертора можно снимать и настройки можно менять полностью локально,
не подключаясь к облаку. WiFi-донгл SmartESS — это лишь мост, который по проводу
опрашивает инвертор штатным протоколом и ретранслирует данные в облако. Тот же
самый обмен можно вести самому через физический порт инвертора (RS232 / USB /
RS485). Это приложение делает именно это.

Инвертор относится к семейству **Voltronic Power** и говорит по текстовому
протоколу **PI30** («HS», Q-команды) с контрольной суммой **CRC-16/XMODEM**.
Корректность CRC подтверждена эталонными значениями (`QPIGS → B7A9`,
`QPIRI → F854`, `QMOD → 49C1`, `QPIWS → B4DA`, `QID → D6EA`).

## 2. Как это устроено

```
Инвертор ──(RS232/USB/RS485)── Raspberry Pi ──(WiFi/LAN)── твой телефон/браузер
                                    │
                    ┌───────────────┴───────────────┐
                    │  Node.js (этот проект)         │
                    │  ┌──────────┐  ┌────────────┐  │
                    │  │ transport│  │  protocol  │  │
                    │  │ serial   │  │  PI30 +CRC │  │
                    │  │ hid      │  └────────────┘  │
                    │  │ mock     │  ┌────────────┐  │
                    │  └──────────┘  │ HTTP + WS  │  │
                    │                └────────────┘  │
                    └────────────────────────────────┘
```

Слои:

- **`server/src/protocol/`** — реализация PI30: сборка кадров, CRC-16/XMODEM, парсеры
  ответов `QPIGS` (статус), `QPIRI` (номиналы/настройки), `QMOD` (режим),
  `QPIWS` (предупреждения), билдеры setter-команд (`POP`, `PCP`, `MCHGC`,
  `MUCHGC`, `PBCV`, `PBDV`).
- **`server/src/transport/`** — три транспорта c общим интерфейсом и автоопределением:
  - `serial` — RS232 через USB-адаптер или CDC-порт (`serialport`);
  - `hid` — USB-HID (мост Cypress, VID `0x0665` / PID `0x5161`) (`node-hid`);
  - `mock` — реалистичные демо-данные, когда инвертор не подключён.
- **`server/src/inverter.ts`** — опрос по таймеру, очередь команд (сериализация доступа
  к единственному UART), автопереподключение, применение управляющих команд.
- **`server/src/server.ts`** — Express (REST + статика) и WebSocket (живой push).
- **`web/`** — мобильный веб-интерфейс на Next.js; статический экспорт
  (`web/out/`) раздаёт тот же Express-сервер.

## 3. Подключение инвертора к Pi (железо)

> На момент установки инвертор **не был подключён** к Pi — приложение работает в
> режиме демо-данных и **автоматически подхватит** инвертор, как только он
> появится (нужно перезапустить сервис или дождаться цикла переподключения).

1. **Вынь штатный WiFi-донгл SmartESS** из порта инвертора. RS232 и USB у
   Voltronic обычно висят на одном внутреннем UART — два опросчика одновременно
   конфликтуют, поэтому активным должен быть один.
2. Подключи Pi к инвертору одним из способов:
   - **USB→USB** (проще всего, без переходников). Инвертор часто определяется как
     USB-HID (`/dev/hidraw*`), реже как serial (`/dev/ttyUSB*`).
   - **RS232 инвертора → USB-RS232 адаптер → USB Pi** («чистый» serial
     `/dev/ttyUSB0`, без HID-нюансов). Скорость обычно **2400** бод.
3. Перезапусти сервис: `sudo systemctl restart inverter-monitor`.
4. Проверь, что в шапке интерфейса статус сменился с «Демо-данные» на
   «Подключено · serial/hid …».

Если Pi не видит устройство: `lsusb`, `ls -l /dev/ttyUSB* /dev/hidraw*`, и права
(пользователь `pi` должен быть в группе `dialout` для serial / `plugdev` для HID).

## 4. Требования

- Raspberry Pi (проверено на Pi 3B, Raspberry Pi OS/Raspbian, armv7l).
- **Node.js ≥ 18** (установлен официальный бинарник v18.20.8 в `/opt`, ссылки в
  `/usr/local/bin`).
- Для сборки нативных модулей: `git`, `gcc`, `make`, `python3` (уже есть на Pi).

## 5. Разработка

Монорепо на npm workspaces: `shared/` (общие типы и API-контракт),
`server/` (Express + WebSocket, протокол PI30) и `web/` (UI на Next.js).
Разработка и сборка ведутся на обычной машине (не на Pi); Node ≥ 20.

```bash
git clone <репозиторий> inverter-monitor
cd inverter-monitor
npm install    # ставит зависимости всех воркспейсов разом
npm run dev    # сервер :3000 (mock-данные) + UI :3001 (Next.js, HMR)
```

Открой `http://localhost:3001` — в dev-режиме UI проксирует `/api/*` на
сервер `:3000` (см. `web/next.config.ts`).

Перед коммитом — статическая проверка (typecheck сервера и веба, selfcheck
протокола PI30/CRC):

```bash
npm run check
```

## 6. Деплой на Pi

Сборка — целиком **локальная**: Pi ничего не компилирует, только
устанавливает production-зависимости сервера и рестартует systemd-сервис.

```bash
./deploy.sh
```

Что делает скрипт:
1. `npm run build` (shared → server → web) и `npm run check`.
2. `rsync` заливает на Pi собранные артефакты — `shared/dist`, `server/dist`,
   `server/systemd`, `server/.env.example`, статику `web/out` — и
   `package.json`/`package-lock.json` воркспейсов.
3. По SSH на Pi: одноразово мигрирует старую раскладку (`data/` →
   `server/data/`, `.env` → `server/.env`, удаляет старые `dist/`, `src/`,
   `public/`), ставит `npm ci -w server --omit=dev`, обновляет systemd-юнит
   и рестартует `inverter-monitor`.
4. Проверяет `GET /api/health` (до минуты на рестарт пода); `200` без
   авторизации или `401` с авторизацией — оба означают «сервер жив».

Настройки — через переменные окружения:

```bash
PI_HOST=pi@192.168.1.112 SSH_KEY=~/.ssh/pi_key ./deploy.sh
```

- `PI_HOST` — пользователь и адрес Pi (по умолчанию `pi@192.168.1.112`).
- `SSH_KEY` — путь к приватному ключу, если он не подхватывается ssh-агентом
  по умолчанию.

На Pi конфиг и данные теперь лежат в `server/.env` и `server/data/`
(`baseline.json`, `sessions.json` — как и раньше, просто путь переехал под
`server/`); статику отдаёт сам сервер из `web/out/`.

Юнит копируется и рестартуется при каждом деплое автоматически, но
`systemctl enable` (автозапуск после перезагрузки Pi) — разовая ручная
операция:

```bash
ssh pi@192.168.1.112 sudo systemctl enable inverter-monitor
```

## 7. Конфигурация (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт HTTP/WS сервера |
| `HOST` | `0.0.0.0` | Интерфейс прослушивания |
| `INVERTER_TRANSPORT` | `auto` | `auto` / `serial` / `hid` / `mock` |
| `INVERTER_SERIAL_DEVICE` | — | Путь к serial-устройству (иначе автоподбор) |
| `INVERTER_BAUD` | `2400` | Скорость serial |
| `POLL_INTERVAL_MS` | `5000` | Период опроса |
| `COMMAND_TIMEOUT_MS` | `3000` | Таймаут команды |
| `ALLOW_MOCK` | `true` | Демо-данные, если инвертор не найден |
| `ALLOW_CONTROL` | `true` | Мастер-выключатель записи. `false` = только чтение навсегда (разблокировать нельзя) |
| `STARTUP_LOCKED` | `true` | Стартовать в режиме «только чтение» (запись требует явной разблокировки) |
| `AUTO_RELOCK` | `true` | Автоматически возвращать блокировку после каждой успешной записи |
| `DATA_DIR` | `data` | Куда сохранять эталон настроек (`baseline.json`) |
| `AUTH_PASSWORD` | — | Пароль входа в UI/API. Пусто = без авторизации (доверенная LAN) |
| `AUTH_SESSION_TTL_DAYS` | `30` | Срок жизни сессионной cookie |

### Авторизация

При заданном `AUTH_PASSWORD` весь UI, API и WebSocket требуют входа
(страница `/login.html`, HttpOnly-cookie, сессии переживают рестарт —
`server/data/sessions.json` хранит только SHA-256 токенов). После 5 неверных паролей
с одного IP — блокировка на 10 минут. Выход — ссылка «выйти» в подвале или
`POST /api/logout`.

**Перед пробросом порта на роутере**: обязательно задать `AUTH_PASSWORD`.
Голый HTTP наружу отдаёт пароль и cookie открытым текстом — снаружи лучше
заходить через VPN (WireGuard) или поставить перед приложением reverse proxy
с TLS (caddy/nginx + Let's Encrypt).

## 8. Веб-интерфейс

- **Шапка**: статус подключения (Подключено / Демо-данные / Нет связи), текущий
  режим (От сети / От батареи / …), время последнего обновления.
- **Батарея**: заряд (SoC, кольцо), напряжение, ток заряда/разряда, состояние.
- **Солнце (PV)**: мощность, напряжение, ток.
- **Нагрузка**: активная мощность, полная (ВА), % загрузки, напряжение/частота.
- **Сеть**: напряжение, частота, температура радиатора.
- **Текущие настройки и эталон** (сворачиваемая панель): таблица настроек
  «Сейчас / Эталон» с подсветкой расхождений, список функций-флагов, кнопка
  «Перечитать эталон».
- **Управление** (сворачиваемая панель): вверху — статус блокировки и кнопка
  «Разблокировать/Заблокировать». Пока заблокировано, элементы управления
  неактивны. Ниже: приоритет источника выхода/заряда, макс. ток заряда, макс. ток
  заряда от сети. Каждое изменение — с подтверждением, после записи блокировка
  возвращается автоматически.
- **Продвинутое**: отправка произвольной query-команды PI30.

Обновление — в реальном времени по WebSocket с автопереподключением.

## 9. API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/login` | `{password}` — вход, ставит сессионную cookie |
| `POST` | `/api/logout` | Выход, отзывает сессию |
| `GET` | `/api/health` | Проверка живости |
| `GET` | `/api/snapshot` | Текущий снимок (статус, режим, настройки, предупреждения) |
| `GET` | `/api/meta` | Справочники значений для управления |
| `POST` | `/api/control` | `{type, value}` — записать настройку (whitelist; отклоняется при блокировке) |
| `POST` | `/api/lock` | `{locked}` — включить/снять блокировку записи |
| `GET` | `/api/baseline` | Эталон настроек, снятый при подключении |
| `POST` | `/api/baseline/recapture` | Свежее чтение настроек из инвертора и перезапись эталона |
| `POST` | `/api/raw` | `{command}` — произвольная команда PI30; не-query (без префикса `Q`) требуют снятой блокировки |
| `WS` | `/ws` | Push снимков в реальном времени |

Типы для `/api/control`: `outputSourcePriority`, `chargerSourcePriority`,
`maxChargingCurrent`, `maxAcChargingCurrent`, `batteryRechargeVoltage`,
`batteryRedischargeVoltage`.

Пример:
```bash
curl -X POST http://192.168.1.112:3000/api/control \
  -H 'Content-Type: application/json' \
  -d '{"type":"chargerSourcePriority","value":3}'   # 3 = Only Solar
```

## 10. Подключение к Home Assistant (MQTT)

Приложение умеет публиковать данные в **MQTT с автодискавери Home Assistant** —
HA сам создаёт все сущности, YAML писать не нужно. По умолчанию интеграция
**выключена** (пустой `MQTT_URL`); приложение работает как обычно.

**Что нужно:**
1. Рабочий **MQTT-брокер** (обычно аддон **Mosquitto** в Home Assistant) и
   включённая интеграция **MQTT** в HA. Запиши адрес брокера и логин/пароль.
2. В `server/.env` приложения указать брокер и перезапустить сервис:
   ```
   MQTT_URL=mqtt://ha-user:ha-pass@IP-БРОКЕРА:1883
   # опционально — управление инвертором из HA (обходит блокировку записи в UI):
   MQTT_ENABLE_CONTROL=true
   ```
   ```
   sudo systemctl restart inverter-monitor
   ```
3. В HA во вкладке **Настройки → Устройства и службы → MQTT** появится устройство
   **«Inverter SK-5500P-48L»** со всеми сенсорами.

**Что публикуется:**
- Сенсоры: PV (Вт/В/А), заряд батареи, напряжение, ток заряда/разряда, нагрузка
  (Вт/ВА/%), выходное напряжение/частота, сеть, температура, режим, предупреждения.
- Бинарные сенсоры: «на связи» (connectivity), «авария/предупреждение» (problem),
  «запись заблокирована» (lock).
- Настройки: при `MQTT_ENABLE_CONTROL=false` — только для чтения; при `true` —
  как управляемые `select` (приоритеты источника выхода/заряда, макс. ток заряда,
  макс. ток заряда от сети).

**Топики:** состояние — `inverter/<node>/state` (JSON), доступность —
`inverter/<node>/availability`, команды — `inverter/<node>/set/<param>`,
discovery — `homeassistant/<component>/<node>/<key>/config`. Node id и префиксы
настраиваются (`MQTT_NODE_ID`, `MQTT_BASE_TOPIC`, `MQTT_DISCOVERY_PREFIX`).

**Важно про управление из HA:** `MQTT_ENABLE_CONTROL=true` разрешает запись из HA
в обход блокировки «только чтение» веб-интерфейса — сам этот флаг и есть
осознанное разрешение. Команды по-прежнему проходят валидацию/whitelist.

> Примечание: сам Home Assistant на текущий Pi (Raspbian 10 buster, 32-бит,
> ~1 ГБ ОЗУ) не встанет — HA уже только 64-битный и требует Python ≥ 3.13, а Pi 3B
> ниже рекомендованной для HA конфигурации. HA стоит запускать на 64-битной ОС
> (Bookworm) и/или на более мощном узле; это приложение к нему подключится по MQTT
> откуда угодно в сети.

## 11. ⚠️ Безопасность управления и блокировка записи

Приложение спроектировано по принципу **«читаем, но не перезаписываем, пока это
не понадобится»**:

- **Ничего не пишется автоматически.** Опрос и подключение шлют только read-команды
  (`QPIGS`, `QMOD`, `QPIRI`, `QFLAG`, `QPIWS`, `QID`). Запись происходит
  исключительно по явному действию.
- **Блокировка записи включена по умолчанию** (`STARTUP_LOCKED=true`). Пока не
  нажмёшь «Разблокировать» в интерфейсе (или не вызовешь `POST /api/lock`),
  любые setter-команды отклоняются — и через UI, и через API.
- **Авто-возврат блокировки** после каждой успешной записи (`AUTO_RELOCK=true`):
  разблокировал → изменил один параметр → снова заблокировано.
- **Эталон настроек**: при первом подключении устройства все текущие настройки
  (`QPIRI` + `QFLAG`) один раз считываются и сохраняются на диск
  (`server/data/baseline.json`), с привязкой к серийному номеру (`QID`). В интерфейсе
  видно эталон и **подсветку расхождений** (drift), если текущее значение
  отличается от снятого при подключении. Кнопка «Перечитать эталон» обновляет его
  вручную. При подключении другого устройства (например, реального инвертора
  вместо демо) эталон захватывается заново автоматически.
- **Чтение безопасно, запись — нет.** Меняя пороги напряжений, токи заряда и
  приоритеты, можно навредить батарее или нагрузке. Меняй по одному параметру.
- Все setter-команды проходят через **whitelist** с валидацией; инвертор отвечает
  `ACK`/`NAK`. Диапазоны/коды у клонов Voltronic слегка различаются — **перед
  первой записью на реальном инверторе** сверься со своей прошивкой.
- Чтобы полностью и необратимо запретить запись — `ALLOW_CONTROL=false`
  (в этом режиме разблокировать нельзя).

## 12. Что проверено, а что требует реального инвертора

**Проверено (без железа):**
- CRC-16/XMODEM — совпадает с эталонными значениями Voltronic.
- Сборка/разбор кадров PI30, round-trip.
- Сервер, все REST-эндпоинты, WebSocket, веб-интерфейс — в mock-режиме.
- Сборка TypeScript, установка на Pi, автозапуск через systemd.

**Требует проверки на подключённом инверторе:**
- Реальный транспорт (serial vs HID) и точный бод.
- Порядок и единицы полей `QPIGS`/`QPIRI` именно у твоей прошивки (парсеры
  устойчивы и хранят `raw`, но маппинг индексов стоит сверить).
- Точные коды/диапазоны setter-команд (особенно `MCHGC`/`MUCHGC`).
- HID-кадрирование (реализовано по типовой схеме mpp-solar).

Рекомендация для сверки — эталонный `mpp-solar`:
```bash
pip install mppsolar
mpp-solar -p /dev/hidraw0 -c QPIGS      # или -p /dev/ttyUSB0
```

## 13. Про обновление системы (важно)

На Pi установлена **Raspbian 10 (buster)** — релиз снят с поддержки (EOL).
Главный репозиторий Raspbian для buster уже недоступен (404), поэтому штатный
`apt upgrade` в пределах buster ничего значимого не тянет (доступно только
обновление загрузчика `rpi-eeprom`, которое на удалённой headless-машине трогать
рискованно). Полный переход buster → bookworm удалённо и без подтверждения не
выполнялся — это рискованная операция.

**Рекомендация:** запланировать чистую установку актуального **Raspberry Pi OS
(Bookworm)** на отдельную SD-карту. На работу этого приложения EOL никак не
влияет (Node 18 поставлен отдельным бинарником, не из apt).

## 15. Траблшутинг

- **«Демо-данные» вместо реальных** — инвертор не найден. Проверь подключение
  (`lsusb`, `/dev/ttyUSB*`, `/dev/hidraw*`), права, вынь штатный донгл, задай
  `INVERTER_SERIAL_DEVICE` и/или `INVERTER_TRANSPORT` явно.
- **CRC mismatch в логах** — не тот бод или битый кабель. Попробуй другой бод,
  сверься с `mpp-solar`.
- **`NAK` на запись** — команда/значение не поддерживается этой прошивкой.
  Сверься с `QPIRI` и документацией своей модели.
- **Порт занят** — активен только один опросчик; убедись, что штатный донгл вынут
  и не запущены параллельные экземпляры.
