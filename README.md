# 🔋 Inverter Monitor — SK-5500P-48L

**Локальный мониторинг и управление гибридным инвертором напрямую — без облака SmartESS.**

![TypeScript](https://img.shields.io/badge/TypeScript-5.4-3178C6?logo=typescript&logoColor=white)

Веб-приложение на TypeScript / Node.js для мониторинга и управления гибридным инвертором
**SK-5500P-48L** (семейство **Voltronic Power** / SmartESS / WatchPower). Работает на
Raspberry Pi, опрашивает инвертор напрямую по serial / USB-HID штатным протоколом **PI30**,
отдаёт мобильный веб-интерфейс и REST/WebSocket API в локальную сеть. Данные никуда наружу
не уходят.

## ✨ Возможности

- 📡 **Прямой опрос инвертора** по протоколу PI30 (CRC-16/XMODEM), минуя облако и приложение SmartESS.
- 🔀 **Три транспорта с автоопределением** — serial (RS232/USB), USB-HID (мост Cypress) и mock (демо-данные, когда инвертор не подключён).
- 📱 **Мобильный веб-интерфейс** (Next.js) с живым обновлением по WebSocket и автопереподключением.
- 🌍 **Интерфейс на трёх языках** — украинский, русский, английский; переключение без перезагрузки.
- 🔒 **Безопасное управление** — по умолчанию только чтение; запись под явной разблокировкой, whitelist команд, авто-возврат блокировки, эталон настроек с подсветкой расхождений (drift).
- 🏠 **Интеграция с Home Assistant** по MQTT с автодискавери — сущности появляются в HA сами, YAML писать не нужно.
- 🔑 **Авторизация** (опционально) — вход по паролю, HttpOnly-сессии, защита от перебора.
- 🚀 **Один скрипт деплоя** — локальная сборка → rsync на Pi → рестарт systemd → health-check.

## 🗺️ Как это устроено

```
Инвертор ──(RS232/USB/RS485)── Raspberry Pi ──(WiFi/LAN)── телефон / браузер
                                    │
                    ┌───────────────┴───────────────┐
                    │  Node.js (этот проект)         │
                    │  ┌──────────┐  ┌────────────┐  │
                    │  │ transport│  │  protocol  │  │
                    │  │ serial   │  │  PI30 +CRC │  │
                    │  │ hid      │  └────────────┘  │
                    │  │ mock     │  ┌────────────┐  │
                    │  └──────────┘  │ HTTP + WS  │  │
                    │                └────────────┘  │
                    └────────────────────────────────┘
```

WiFi-донгл SmartESS — это лишь мост: он по проводу опрашивает инвертор штатным протоколом
и ретранслирует данные в облако. Тот же обмен можно вести самому через физический порт
инвертора (RS232 / USB / RS485) — приложение делает именно это.

**Слои** (монорепо на npm workspaces):

| Слой | Где | Ответственность |
|---|---|---|
| `shared` | `shared/src` | Общие типы (`Snapshot`, …) и контракт управления (whitelist, справочники) — общий для сервера и веба |
| `protocol` | `server/src/protocol` | PI30: сборка/разбор кадров, CRC-16/XMODEM, парсеры `QPIGS`/`QPIRI`/`QMOD`/`QPIWS`/`QFLAG`, билдеры setter-команд |
| `transport` | `server/src/transport` | `serial` / `hid` / `mock` за общим интерфейсом + автоопределение |
| `inverter` | `server/src/inverter.ts` | Опрос по таймеру, очередь команд (один UART), автопереподключение, эталон, блокировка |
| `server` | `server/src/server.ts` | Express (REST + статика) и WebSocket (живой push) |
| `mqtt` | `server/src/mqtt.ts` | Публикация в MQTT с автодискавери Home Assistant |
| `web` | `web/` | Мобильный UI на Next.js; статический экспорт раздаёт тот же Express |

Инвертор относится к семейству **Voltronic Power** и говорит по текстовому протоколу **PI30**
(«HS», Q-команды) с контрольной суммой **CRC-16/XMODEM**. Корректность CRC подтверждена
эталонными значениями (`QPIGS → B7A9`, `QPIRI → F854`, `QMOD → 49C1`, `QPIWS → B4DA`,
`QID → D6EA`).

## 🚀 Быстрый старт (разработка)

Монорепо на npm workspaces: `shared/` (общие типы и API-контракт), `server/` (Express +
WebSocket, протокол PI30) и `web/` (UI на Next.js). Разработка и сборка ведутся на обычной
машине (не на Pi); Node ≥ 20.

```bash
git clone git@github.com:apanamaryov/sweethome.git inverter-monitor
cd inverter-monitor
npm install    # ставит зависимости всех воркспейсов разом
npm run dev    # сервер :3000 (mock-данные) + UI :3001 (Next.js, HMR)
```

Открой `http://localhost:3001` — в dev-режиме UI проксирует `/api/*` на сервер `:3000`
(см. `web/next.config.ts`).

Перед коммитом — статическая проверка (typecheck веба + selfcheck протокола PI30/CRC):

```bash
npm run check
```

> `npm run check` для сервера запускает **`server/scripts/selfcheck.ts`** — это не typecheck,
> а сверка эталонных CRC, раундтрипа кадров и позиционного маппинга парсеров. Гоняй его после
> любых правок в `server/src/protocol/*`.

## 🔌 Подключение инвертора к Pi (железо)

> Пока инвертор физически не подключён, приложение работает в режиме демо-данных и
> **автоматически подхватит** инвертор, как только он появится (после рестарта сервиса или
> цикла переподключения).

1. **Вынь штатный WiFi-донгл SmartESS** из порта инвертора. RS232 и USB у Voltronic обычно
   висят на одном внутреннем UART — два опросчика одновременно конфликтуют, активным должен
   быть один.
2. Подключи Pi к инвертору одним из способов:
   - **USB → USB** (проще всего). Инвертор часто определяется как USB-HID (`/dev/hidraw*`), реже как serial (`/dev/ttyUSB*`).
   - **RS232 инвертора → USB-RS232 адаптер → USB Pi** («чистый» serial `/dev/ttyUSB0`, без HID-нюансов). Скорость обычно **2400** бод.
3. Перезапусти сервис: `sudo systemctl restart inverter-monitor`.
4. Проверь, что в шапке интерфейса статус сменился с «Демо-данные» на «Подключено · serial/hid …».

Если Pi не видит устройство: `lsusb`, `ls -l /dev/ttyUSB* /dev/hidraw*`, и права (пользователь
`pi` должен быть в группе `dialout` для serial / `plugdev` для HID).

**Требования:** Raspberry Pi (проверено на Pi 3B), **Node.js ≥ 18**; для сборки нативных
модулей serial/HID — `git`, `gcc`, `make`, `python3`.

## 📦 Деплой на Pi

Сборка — целиком **локальная**: Pi ничего не компилирует, только устанавливает
production-зависимости сервера и рестартует systemd-сервис.

```bash
./deploy.sh
# c параметрами:
PI_HOST=pi@192.168.1.112 SSH_KEY=~/.ssh/pi_key ./deploy.sh
```

Что делает скрипт:

1. `npm run build` (shared → server → web) и `npm run check`.
2. `rsync` заливает на Pi собранные артефакты — `shared/dist`, `server/dist`, `server/systemd`, `server/.env.example`, статику `web/out` — и `package.json`/`package-lock.json` воркспейсов.
3. По SSH на Pi: одноразово мигрирует старую раскладку (`data/` → `server/data/`, `.env` → `server/.env`), ставит `npm ci -w server --omit=dev`, обновляет systemd-юнит и рестартует `inverter-monitor`.
4. Проверяет `GET /api/health` (до минуты на рестарт пода); `200` без авторизации или `401` с авторизацией — оба означают «сервер жив».

- `PI_HOST` — пользователь и адрес Pi (по умолчанию `pi@192.168.1.112`).
- `SSH_KEY` — путь к приватному ключу, если он не подхватывается ssh-агентом.

На Pi конфиг и данные лежат в `server/.env` и `server/data/` (`baseline.json`, `sessions.json`);
статику отдаёт сам сервер из `web/out/`. Автозапуск после перезагрузки Pi (`systemctl enable`) —
разовая ручная операция:

```bash
ssh pi@192.168.1.112 sudo systemctl enable inverter-monitor
```

## ⚙️ Конфигурация (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт HTTP/WS сервера |
| `HOST` | `0.0.0.0` | Интерфейс прослушивания |
| `INVERTER_TRANSPORT` | `auto` | `auto` / `serial` / `hid` / `mock` |
| `INVERTER_SERIAL_DEVICE` | — | Путь к serial-устройству (иначе автоподбор) |
| `INVERTER_BAUD` | `2400` | Скорость serial |
| `POLL_INTERVAL_MS` | `5000` | Период опроса |
| `COMMAND_TIMEOUT_MS` | `3000` | Таймаут команды |
| `ALLOW_MOCK` | `true` | Демо-данные, если инвертор не найден |
| `ALLOW_CONTROL` | `true` | Мастер-выключатель записи. `false` = только чтение навсегда (разблокировать нельзя) |
| `STARTUP_LOCKED` | `true` | Стартовать в режиме «только чтение» (запись требует явной разблокировки) |
| `AUTO_RELOCK` | `true` | Автоматически возвращать блокировку после каждой успешной записи |
| `DATA_DIR` | `data` | Куда сохранять эталон настроек (`baseline.json`) |
| `AUTH_PASSWORD` | — | Пароль входа в UI/API. Пусто = без авторизации (доверенная LAN) |
| `AUTH_SESSION_TTL_DAYS` | `30` | Срок жизни сессионной cookie |
| `MQTT_URL` | — | Адрес MQTT-брокера (`mqtt://user:pass@host:1883`). Пусто = MQTT выключен |
| `MQTT_ENABLE_CONTROL` | `false` | Управляемые сущности в HA (в обход UI-блокировки) |

Полный список MQTT-переменных — в [`server/.env.example`](server/.env.example).

### 🔑 Авторизация

При заданном `AUTH_PASSWORD` весь UI, API и WebSocket требуют входа (страница `/login`,
HttpOnly-cookie, сессии переживают рестарт — `server/data/sessions.json` хранит только SHA-256
токенов). После 5 неверных паролей с одного IP — блокировка на 10 минут.

> **Перед пробросом порта на роутере** обязательно задай `AUTH_PASSWORD`. Голый HTTP наружу
> отдаёт пароль и cookie открытым текстом — снаружи лучше заходить через VPN (WireGuard) или
> reverse proxy с TLS (caddy/nginx + Let's Encrypt).

## 🖥️ Веб-интерфейс

- **Шапка** — статус подключения (Подключено / Демо-данные / Нет связи), текущий режим (От сети / От батареи / …), время последнего обновления.
- **Батарея** — заряд (SoC, кольцо), напряжение, ток заряда/разряда, состояние.
- **Солнце (PV)** — мощность, напряжение, ток.
- **Нагрузка** — активная мощность, полная (ВА), % загрузки, напряжение/частота.
- **Сеть** — напряжение, частота, температура радиатора.
- **Текущие настройки и эталон** — таблица «Сейчас / Эталон» с подсветкой расхождений, флаги-функции, кнопка «Перечитать эталон».
- **Управление** — статус блокировки и кнопка «Разблокировать/Заблокировать»; приоритет источника выхода/заряда, макс. ток заряда, макс. ток заряда от сети. Каждое изменение — с подтверждением, после записи блокировка возвращается автоматически.
- **Продвинутое** — отправка произвольной query-команды PI30.

Обновление — в реальном времени по WebSocket с автопереподключением.

## 🏠 Подключение к Home Assistant (MQTT)

Приложение умеет публиковать данные в **MQTT с автодискавери Home Assistant** — HA сам создаёт
все сущности. По умолчанию интеграция **выключена** (пустой `MQTT_URL`).

1. Рабочий **MQTT-брокер** (обычно аддон **Mosquitto** в HA) и включённая интеграция **MQTT**.
2. В `server/.env` указать брокер и перезапустить сервис:
   ```bash
   MQTT_URL=mqtt://ha-user:ha-pass@IP-БРОКЕРА:1883
   # опционально — управление инвертором из HA (обходит UI-блокировку записи):
   MQTT_ENABLE_CONTROL=true
   sudo systemctl restart inverter-monitor
   ```
3. В HA (**Настройки → Устройства и службы → MQTT**) появится устройство **«Inverter SK-5500P-48L»** со всеми сенсорами.

**Публикуется:** сенсоры PV/батареи/нагрузки/сети/температуры/режима/предупреждений; бинарные
сенсоры «на связи», «авария», «запись заблокирована»; при `MQTT_ENABLE_CONTROL=true` —
управляемые `select` (приоритеты источника, токи заряда).

**Топики:** состояние — `inverter/<node>/state` (JSON), доступность — `inverter/<node>/availability`,
команды — `inverter/<node>/set/<param>`, discovery — `homeassistant/<component>/<node>/<key>/config`.

> `MQTT_ENABLE_CONTROL=true` разрешает запись из HA в обход UI-блокировки — сам флаг и есть
> осознанное разрешение. Команды по-прежнему проходят валидацию/whitelist.
>
> Сам Home Assistant на старый Pi 3B (32-бит, ~1 ГБ ОЗУ) не встанет — HA уже только 64-битный.
> HA стоит запускать на 64-битной ОС и/или более мощном узле; это приложение подключится к нему
> по MQTT откуда угодно в сети.

## 🔒 Безопасность управления и блокировка записи

Приложение спроектировано по принципу **«читаем, но не перезаписываем, пока это не понадобится»**:

- **Ничего не пишется автоматически.** Опрос и подключение шлют только read-команды. Запись — исключительно по явному действию.
- **Блокировка записи включена по умолчанию** (`STARTUP_LOCKED=true`). Пока не нажмёшь «Разблокировать» (или не вызовешь `POST /api/lock`), любые setter-команды отклоняются — и через UI, и через API.
- **Авто-возврат блокировки** после каждой успешной записи (`AUTO_RELOCK=true`).
- **Эталон настроек** — при первом подключении все текущие настройки (`QPIRI` + `QFLAG`) один раз считываются и сохраняются на диск, с привязкой к серийному номеру (`QID`). В интерфейсе видно **подсветку расхождений** (drift). При подключении другого устройства эталон захватывается заново.
- **Чтение безопасно, запись — нет.** Меняя пороги напряжений, токи заряда и приоритеты, можно навредить батарее или нагрузке. Меняй по одному параметру.
- Все setter-команды проходят через **whitelist** с валидацией; инвертор отвечает `ACK`/`NAK`. Диапазоны/коды у клонов Voltronic слегка различаются — **перед первой записью на реальном инверторе** сверься со своей прошивкой.
- Полный необратимый запрет записи — `ALLOW_CONTROL=false` (разблокировать нельзя).

## 🧪 Что проверено, а что требует реального инвертора

**Проверено (без железа):**

- CRC-16/XMODEM — совпадает с эталонными значениями Voltronic.
- Сборка/разбор кадров PI30, round-trip.
- Сервер, все REST-эндпоинты, WebSocket, веб-интерфейс — в mock-режиме.
- Сборка TypeScript, установка на Pi, автозапуск через systemd.

**Требует проверки на подключённом инверторе:**

- Реальный транспорт (serial vs HID) и точный бод.
- Порядок и единицы полей `QPIGS`/`QPIRI` именно у твоей прошивки (парсеры устойчивы и хранят `raw`, но маппинг стоит сверить).
- Точные коды/диапазоны setter-команд (особенно `MCHGC`/`MUCHGC`).
- HID-кадрирование (реализовано по типовой схеме mpp-solar).

Эталон для сверки — `mpp-solar`:

```bash
pip install mppsolar
mpp-solar -p /dev/hidraw0 -c QPIGS      # или -p /dev/ttyUSB0
```

## 🛠️ Траблшутинг

- **«Демо-данные» вместо реальных** — инвертор не найден. Проверь подключение (`lsusb`, `/dev/ttyUSB*`, `/dev/hidraw*`), права, вынь штатный донгл, задай `INVERTER_SERIAL_DEVICE` / `INVERTER_TRANSPORT` явно.
- **CRC mismatch в логах** — не тот бод или битый кабель. Попробуй другой бод, сверься с `mpp-solar`.
- **`NAK` на запись** — команда/значение не поддерживается этой прошивкой. Сверься с `QPIRI` и документацией модели.
- **Порт занят** — активен только один опросчик; убедись, что штатный донгл вынут и не запущены параллельные экземпляры.
